# 疲労ロジック構造監査（2026-09-08）

## 監査範囲

標準版のコードと保存済み疲労CSVを読み取り、標準版を変更せずに監査した。
対象は `scripts/06_calculate_fatigue.py`、`scripts/11_prediction_01.py`、
`scripts/fatigue_merge.py`、J1/J2 2026疲労CSV計760行、保存済みtotoスナップショットである。

## 結論

現行値は純粋な疲労計測値ではない。休養不足、移動、開催地、過去に計算した総疲労を
一つに合算した「複合補正値」である。固定アウェー4点は疲労というより開催地効果で、
HFAとの概念重複がある。持越しは前回の総疲労を再入力する再帰式なので、原因負荷が
3試合で消えず、固定アウェー点や移動負荷も再計上される。

この状態で新しい疲労補正を足すべきではない。先に固定アウェー点を疲労から除外し、
再帰持越しを原因データからの有限窓集計へ置き換えたシャドーを作るのが優先である。

## 1. 固定アウェー4点

`AWAY_GAME_PENALTY = 4` が全アウェーチームへ無条件に加算される。これは距離0kmでも、
十分な休養があっても発生し、`FATIGUE_GOAL_SCALING = 0.01` により直接 -0.04 xGとなる。
さらにこの4点を含む総疲労が後続の状態評価・試合分類・ルール閾値にも入る。

J1は既定値で `HFA_ELO=0`、`HFA_PROB_WEIGHT=0` だが、固定アウェー点が全試合で
アウェー側だけを下げるため、疲労経由の隠れたHFAとして働く。J2は既定で
`HFA_ELO=12`、`HFA_PROB_WEIGHT=0.35` に加え、ホーム／アウェー成績差の特徴も持つ。
したがってJ2では明示HFAとの二重計上候補、J1ではHFA無効という設定意図との矛盾になる。

優先度は最上位。シャドーでは固定4点を0にし、開催地効果はHFA側だけで扱う。
連続アウェーは別の `schedule_load` として、実際の並びから限定的に評価する。

## 2. 再帰的持越し

現行は各試合で次を計算する。

```
F_t = direct_t + 0.35 F_(t-1) + 0.20 F_(t-2) + 0.10 F_(t-3)
```

ここで過去の `F` 自体に、それ以前の持越しが含まれる。一度だけ大きな負荷 `L` が
発生しても、後続係数は `0.35L, 0.3225L, 0.282875L, ...` となり、3試合では消えない。
14日を超える空白でリセットされるまで再帰が続く。継続日程に対する総応答は理論上
`1 / (1 - 0.35 - 0.20 - 0.10) = 2.857` 倍である。単純な当該試合＋直近3試合の
有限加重なら1.65倍なので、現行は意図以上に古い負荷を残し得る。

固定アウェー4点と移動負荷も `F` に含まれるため、過去に評価済みの開催地・移動効果が
後のホーム戦を含めて再計上される。これは明確な構造的二重計上である。

## 3. 成分支配

J1/J2 2026の疲労CSV計760行を合算した、保存列上の寄与率は次のとおり。

| 保存成分 | 総疲労点に対する比率 |
|---|---:|
| 直近負荷持越し | 56.7% |
| 固定アウェー加点 | 27.6% |
| 当該試合の移動距離 | 15.2% |
| 休養不足 | 0.5% |

持越し56.7%の内部には過去の固定アウェー点、移動、休養、さらに古い持越しが混在する。
したがって真の原因別寄与は現行CSVだけでは復元できない。少なくとも、精密化した
`rest_hours` の影響は固定値と再帰項にほぼ埋もれている。

## 4. 現行値が使われる場所

総疲労は次の複数経路に入る。

1. チームごとの期待得点を `総疲労 × 0.01` 減点する。
2. BASE/LAB/MAIN向け状態特徴と疲労差特徴を作る。
3. adverse、focus stability、試合強度・安定性を作る。
4. draw / balanced / swing と近接試合の分類へ入る。
5. J1/J2のサイド復元規則の閾値へ入る。
6. それらを通じてBuyPlanの本命・カバー配分へ間接的に入る。

同じ総疲労値を異なる派生判断が参照するため、厳密な加算二重計上とは限らないものの、
一つの誤差が複数の閾値を同時にまたいで増幅される構造である。影響量は -0.01 xGだけでは
評価できない。

## 5. 計測済みだが予測で分離利用されない情報

`rest_hours`、移動km、7日／14日試合数、外部試合件数、出場時間、延長時間、主力投入率、
確認済み／未確認状態は保存・QCには利用できる。しかし標準予測の主入力は合算済み
`home/away_total_fatigue_score` で、これらを原因別の異なる作用として直接は使わない。

外部試合について実負荷がない場合は0点が履歴へ入る。未確認フラグは残るが、予測値の
不確実性には接続されない。確認状態を0負荷と同義にしない設計が必要である。

## 6. シャドー版の原因別設計

各チーム・対象時刻について、次を独立列として算出する。

| 軸 | 入力 | 推奨する性質 |
|---|---|---|
| `recovery_load` | 実時間の休養 | 96時間付近から急になる非線形関数 |
| `match_load` | 7日／14日の実出場分、試合数、延長 | 元イベントから有限窓で再計算 |
| `travel_load` | 各遠征の距離と経過時間 | 距離の単純比例と飽和型を比較 |
| `rotation_load` | 主力の出場分・連続出場 | 確認値優先、推定値は別列 |
| `schedule_load` | 連戦、連続アウェー | 開催地そのものではなく日程構造 |
| `measurement_uncertainty` | 未確認試合・分数・移動 | 疲労0ではなく信頼度低下として保持 |

休養は実時間を使う。候補例は144時間超をほぼ0、120～144時間を小、96～120時間を中、
72～96時間を大、72時間未満を最大域とする区分線形または滑らかなロジスティック関数。
境界値は固定採用せずシャドーで比較する。

移動は `当該遠征距離` と `直近14日の遠征履歴` を別にする。固定アウェー点は置かない。
距離効果は線形、平方根、区分線形（近距離／中距離／長距離）の候補を比較する。

カップ戦は、確認済み出場分×分数、延長分、主力連続出場を使用する。実績があれば推定を
上書きし、推定しかない場合は点推定を正式値として混ぜず、推定値と信頼度を保持する。

## 7. fatigue_gap と fatigue_total

二軸化は妥当である。ただし単純な総和をそのまま使わず、原因別負荷を標準化してから作る。

```
load_home = f(recovery, match, travel, rotation, schedule)
load_away = f(recovery, match, travel, rotation, schedule)
fatigue_gap = load_home - load_away
fatigue_total = (load_home + load_away) / 2
```

`fatigue_gap` は勝敗方向への小さい補正に使う。符号規約を固定し、上限を設ける。
`fatigue_total` はH/D/Aのどれかへ直接寄せず、本命確率から残る2結果へ確率を再配分する
uncertainty量に使う。再配分後はエントロピーが低下しないことを必須検査とする。

両軍高疲労が常に不確実性を増やすという因果は未検証なので、これは仮説である。
低得点化、選手層による差、強豪側のローテーション耐性など別作用もあり得るため、
方向補正とuncertainty補正を別アームで評価する。

## 8. 荒天uncertaintyとの共通化

共通の「最終確率再配分器」は利用できる。ただし原因スコアは分離保存する。

```
weather_uncertainty
fatigue_total_uncertainty
measurement_uncertainty
combined_uncertainty = capped_combination(...)
```

単純加算は避け、上限付き和または `1 - Π(1-u_i)` を候補とする。荒天と疲労が同時発生しても
二重に大きく動かない上限が必要。各要因の単独差分と結合差分を保存する。

## 9. 安全なシャドー構成

標準版のファイルと関数を変更せず、凍結した試合前入力から次の比較アームを作る。

1. `baseline_frozen`: 購入時標準版。
2. `debiased_components`: 固定4点なし、再帰なし、原因別負荷のみ。方向補正だけ。
3. `debiased_plus_total_uncertainty`: 2に両軍総負荷の不確実性を追加。
4. `debiased_plus_combined_uncertainty`: 3に荒天を共通レイヤーで追加。

各アームは独立してbaselineから生成し、補正を順次使い回さない。入力ハッシュ、コードハッシュ、
as-of日時、確認／推定状態、各要因の確率差を保存する。同じ10候補券数で、Brier、log loss、
首位的中率、平均・最高的中、未カバー結果、救済数と新規取りこぼしを比較する。

## 10. 過去節の再計算可能性

保存済み購入スナップショットは12回分あるため、標準版の過去実績と分離した事後シャドー比較は
可能。ただし原因別疲労を正確に再構成するには、各節の購入締切以前に利用可能だった日程、
キックオフ時刻、外部試合、出場分、移動情報が必要である。

リーグ日程と距離は再構成しやすい。過去のカップ戦実出場分・ローテーションと当時の取得状態は
不足する可能性が高い。後から判明した実績を使う場合は「事後オラクル」と明記し、試合前に
利用可能だった情報だけの `asof_shadow` と混ぜない。

保存先は `data/eval/fatigue_shadow/{version}/{round}/` とし、既存の
`data/eval/toto_rounds/{round}/snapshot` や正式成績を上書きしない。

## 修正優先順位

1. 固定アウェー4点を0にした単独アブレーション。
2. 再帰持越しを原因別有限窓へ置換した単独アブレーション。
3. 1と2を併用した原因別ベースライン。
4. 非線形 `recovery_load` と距離関数の比較。
5. 確認済みカップ戦分数・延長・主力投入の接続。
6. `fatigue_gap` の方向補正。
7. `fatigue_total` のuncertainty補正。
8. 荒天uncertaintyとの上限付き統合。

採用判断は1節の的中数では行わない。先に不要な固定値と再帰を除いた状態を確立し、その後で
各原因の係数とuncertainty仮説を複数節で評価する。
