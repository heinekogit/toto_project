今シーズン運用中 検証チェックリスト

目的
今シーズンの運用期間中に、反映候補の有効性と副作用を確認する。
特に D 過多対策、draw 系分類、buyplan への影響を点検する。

運用前提
- 先シーズンは終了済み
- 本メモは、先シーズン終了後に残した引き継ぎメモを踏まえて、今シーズン運用中の検証整理として使う
- 対象は「今後の数節」または「直近でまとめて見直す対象節」

前提整理
- 当面の正式 policy は home_reversal_watch と j2_draw_trap を中心とする
- それ以外は observation flag として観測し、即時の正式採用はしない
- buyplan は補正器ではなく券面配置器として扱う

毎節の確認対象
- actual H/D/A
- predicted main H/D/A
- main hit rate
- ticket hit rate
- rescue
- harm
- net rescue
- all-same との重なり
- J1/J2 別の傾向
- draw 系総量
- draw_rescue 件数
- draw_watch 件数
- draw_trap 件数

毎節の検証手順
1. 節の predictions / predictions_buyplan_context / buyplan を保存する
2. main prediction の H/D/A 分布を確認する
3. 実結果の H/D/A 分布と比較する
4. draw 系分類の件数を数える
5. purchase_type 別に hit / rescue / harm を集計する
6. ticket_guidance 別に hit / rescue / harm を集計する
7. all-same との重なり件数を確認する
8. draw 系総量と分類別件数が上限感を超えていないか確認する
9. draw_trap が side_with_cover / draw_cut_to_side に逃がせているか確認する
10. 前節までの累積と比べて悪化・改善を判定する

反映候補の基本判定
- 継続観測: 効果はあるがサンプル不足
- 保留: rescue はあるが harm または重複副作用が気になる
- 反映候補: net rescue が安定して正で、再現性もある
- 不採用候補: 一時的な当たりで再現しない、または harm が重い

注意
feature を追加しても、即 policy 接続はしない。
必ず feature -> purchase_type / flag -> 観測 -> rescue/harm -> overlap確認 -> 再現確認 の順で扱う。
