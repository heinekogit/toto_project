## v1：2026年2月開幕対応版

基本構成:

```text
H/D/A予測 → Football LAB補正 → 旧BuyPlan
```

主な特徴:

- Elo、チーム成績、コンディション等からH/D/Aを予測。
- Football LAB情報を最終H/D/A確率へ直接ブレンド。
- BuyPlanは10候補をworld別の役割で生成。
- BuyPlan全体でDを一定比率へ近づける固定D比率を使用。

運用で判明した課題:

- H/Aが不確実な試合と、本当にDになりやすい試合が混同されやすい。
- Football LAB補正がDを直接生成しすぎる。
- 固定D比率が試合ごとの根拠を上書きする。
- D除外後の第2順位展開により、アウェイ偏重が生じる場合がある。
- 本体予測とBuyPlanの券配置問題を分離しにくい。

## v1.x：Dフィルター検証期

2026-2027秋冬シーズンの開幕から第8節まで、v1を使いながらD判別を検証した。

主な検証対象:

- `draw_watch / draw_rescue / draw_trap`
- `j1_false_draw_watch / j2_false_draw_watch / j2_draw_trap`
- `D-core / D-cover / D-uncertain / D-reject`
- DをH/Aへ戻した場合のrescue / harm / net rescue
- リーグ別・節別の再現性
- BuyPlan内のD配置とportfolio cover

この期間に確定した設計判断:

1. Dは目標件数へ合わせて生成しない。
2. 予測結果にDフィルターを適用し、Dの種類と扱いを判断する。
3. 「不確実性」と「引き分けやすさ」を分ける。
4. 固定D比率を廃止する。
5. Football LABから直接H/D/Aを作る構造を改める。
6. 本体予測とBuyPlanの券配置を分けて評価する。

第8節終了をv2.0への大改修の区切りとした。

## v2.0：得点モデル・組合せ確率型BuyPlan

基本構成:

```text

  ↓
ベース λH / λA
  ↓
Football LAB xG対戦補正
  ↓
補正後 λH / λA
  ↓
得点分布
```

- 固定H/D/A比率、固定D数、world記号強制を使わない。
- 候補01は最高確率組合せとする。
- 候補02～10も高確率組合せ群から選ぶ。
- 候補間の過度な類似だけを抑える。

議論抜粋メモ：（v2の次の改修に向けての備考） -------------------------------------------------
現在、「自動的に学習して賢くなる」のではなく、節を重ねることで入力統計が安定する
現在の次期版で節数の蓄積が効く部分は主に以下です。
- 1試合平均得点・失点
- xG・被xG
- Football LABの攻撃xG・被攻撃xG
- シュート・被シュートなどのチーム指標
- 順位・勝点・モチベーション情報
- 疲労や欠場情報の履歴
シーズン序盤は、1試合の大量得点や退場などに平均値が大きく影響されます。節が進むと偶然の影響が薄まり、チームの攻撃力・守備力の推定が安定するため、ベースλとLab対戦補正の信頼性は上がると考えられます。
一方、現在実装した次期版には、次の機能はまだありません。
- 試合結果を受けて係数を自動更新するオンライン学習
- 節ごとにLab補正25%を再推定する処理
- Dフィルター閾値の自動更新
- BuyPlanの確率下限50%を成績から変更する処理
- 過去の予測誤差を次回予測へ直接フィードバックする処理
したがって現状は、
節が進む
→ 累積統計の標本数が増える
→ 入力値が安定する
→ 間接的に予測精度が上がる可能性がある
という構造です。
注意点もあります。累積値だけを使うと、節が進むほど安定する一方、直近の監督交代・戦術変更・主力離脱・急激な好不調への反応が遅くなります。精度向上には、将来的に次の3層へ分けるのが適切です。
1. シーズン累積値
   チームの基礎能力を安定して測る。
2. 直近5試合などの短期値
   現在状態や戦術変化を反映する。
3. 予測誤差の継続監視
   λ、H/D/A確率、D分類が継続的に偏っていないか確認する。
また、序盤はリーグ平均へ強く縮約し、節が進むほど実績値の比重を高める方法も有効です。例えば序盤の3試合平均をそのまま能力値とせず、前年値やリーグ平均と混合し、試合数に応じて当年実績へ移行します。
結論として、現在も節数による自然な安定化はありますが、「結果を学習して精度が上がる仕組み」はまだありません。次期版の正式運用後は、係数を毎節自動調整するより、まず予測誤差を事前固定で蓄積し、一定節数ごとに再校正する方式が安全です。

検証や蓄積についての議論 -----------------------------------------------------------------
蓄積対象は、次の4層に分けるのがよいです。
1. 実行時点の入力を固定保存
結果判明前に、その回で実際に使用したものを保存します。
- 元のpredictions.csv
- v2のnext_predictions.csv
- buyplan.csv・buyplan.html
- 対象toto13試合と並び順
- 欠場情報
- ACL・カップ戦・疲労情報
- Football LABスナップショットの日付
- 天候情報
- 実行日時
- 使用したモデル・BuyPlanバージョン
- 入力欠損や警告
- ファイルのハッシュ値
これは既にスナップショット・観測履歴の仕組みがあります。重要なのは、結果を見た後に同じファイルを上書きしないことです。
2. 予想モデルの評価
結果判明後、BuyPlanとは分離して採点します。
毎節見る項目：
- 本命予想の的中数
- H・D・A別の予想数
- H・D・A別の的中数
- Brier score
- Log loss
- 予測確率帯別の実績
- ベースλとLAB補正後λの差
- LAB補正が救った試合・悪化させた試合
- 予測スコアと実スコア
- ホーム得点・アウェイ得点の予測誤差
- ホーム／アウェイへの偏り
特に大切なのは「当たったか」だけでなく、確率が妥当だったかです。
例えばホーム勝率60%の試合が10試合あれば、6試合程度ホーム勝ちになるのが健全です。10試合中3試合しか勝っていない状態が続けば、確率の過信を疑えます。
3. D分類の評価
Dは独立して蓄積します。
- D-core件数・実D率
- D-cover件数・実D率
- D-uncertain件数・実D率
- D-reject件数・実D率
- D-rejectが正しくDを排除した数
- D-coreを本命にした場合のrescue／harm
- draw_compressed
- flat_draw_trap
- split_side
- リーグ別・試合類型別の成績
D分類は、1～2回の結果で閾値を動かさず、最低10開催回程度まとめて評価します。
4. BuyPlanの評価
予想確率が同じでも、券配置によって結果は変わります。
毎回記録する項目：
- 候補01の的中数
- 候補02～10の各的中数
- 10候補平均
- 10候補中最高
- Portfolio cover
- 候補01から各候補への変更数
- 候補01より改善した候補数
- 候補01より悪化した候補数
- 正解記号を候補群に含められなかった試合
- 含めていたが組合せられなかった試合
- 各候補の組合せ確率
- 確率を落としてカバーを広げた効果
特に失敗を次の2種類に分けるべきです。
予想側の失敗
10候補のどこにも正解記号がない試合です。確率モデルやD分類の問題を疑います。
券配置側の失敗
試合単位では正解記号を含んでいたのに、良い組合せへまとめられなかったケースです。BuyPlanの多様化方法を疑います。
この区別ができることは、v1より大きな進歩です。
試合類型別に残したい項目
母数が増えたら、以下でも集計します。
- J1／J2
- ホーム優勢／互角／アウェイ優勢
- 高得点型／低得点型
- 昇格・残留・上位争い
- ACL・カップ戦前後
- 中2～3日
- 長距離移動
- 欠場影響が大きい試合
- 悪天候
- LAB補正が大きかった試合
- 市場や一般予想と大きく異なった試合
ただし、細分化しすぎると母数が足りなくなるため、最初は全体・J1/J2・H/D/A程度で十分です。
エラー・運用品質も成績として記録
予想精度以外に、次も毎回記録すべきです。
- LAB取得失敗
- 欠損列
- 順位文字列の混入
- チーム名不一致
- toto13試合不一致
- 古いスナップショットの使用
- 欠場情報未更新
- ACL情報未入力
- 生成のやり直し回数
- 結果判明前に正常保存できたか
- 手動補正の有無
「成績が悪かった」のではなく「入力がおかしかった」回を分離できます。
